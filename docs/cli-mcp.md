# CLI and MCP server: design and implementation notes

Phase 4 of [`TODO.md`](TODO.md). Both are thin clients of the admin API
([`admin-api.md`](admin-api.md), [`../openapi.yaml`](../openapi.yaml)). They
are built from the spec at run time, so a new operation in the spec shows
up in both without code changes.

## Decisions

| Topic                     | Decision                                                                                                                                                                                                                                                        | Why                                                                                |
| ------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| Programs                  | `bin/tunnus.js` (CLI, package bin `tunnus`) and `bin/tunnus-mcp.js` (MCP server, bin `tunnus-mcp`). `bin/tunnus-admin.js` stays the database-side bootstrap tool                                                                                                | The CLI and MCP server talk HTTP only and need no database access                  |
| Spec source               | The `openapi.yaml` shipped with the package, loaded with `loadSpec()` from `src/admin/spec.js`. `--spec <file>` (CLI) / `TUNNUS_SPEC` overrides it                                                                                                              | Works offline (help, tests); the server serves the same file for comparison        |
| Command names             | `x-tunnus-cli` on each operation (`users list`, `groups grant`). The `operationId` also works as a command (`tunnus listUsers`). Startup fails if an operation lacks `x-tunnus-cli` or two operations share one                                                 | Readable names without guessing from operation ids                                 |
| Arguments                 | Path, query and top-level request-body properties become `--kebab-case` flags (`userId` → `--user-id`, `display_name` → `--display-name`). Path parameters may also be given positionally, in path order (`tunnus users get <id>`)                              | One rule for every operation                                                       |
| Values                    | Converted by the parameter's or property's schema type: integer, number, boolean (`true`/`false`; a bare boolean flag means `true`), string. Arrays and objects take JSON. `--body <json>` or `--body @file.json` gives the whole body (flags override keys)    | Server-side validation stays the authority; the CLI only converts types            |
| Unknown flags             | Usage error (exit 2) naming the flag and the command's flags                                                                                                                                                                                                    | Typos must not be silently ignored                                                 |
| Help                      | `tunnus --help` lists commands grouped by first word with summaries. `tunnus <command> --help` shows summary, description, flags with type, required, enum, default and description                                                                             |                                                                                    |
| Configuration             | URL and token, in order: `--url` flag, `TUNNUS_URL` / `TUNNUS_ADMIN_TOKEN` env, config file. File: `--config <file>`, else `TUNNUS_CONFIG`, else `$XDG_CONFIG_HOME/tunnus/config.json` (default `~/.config/tunnus/config.json`) with `{ "url", "token" }`       | Common CLI precedence                                                              |
| URL                       | The issuer URL (`https://id.example.org` or `https://example.org/tunnus`); the client appends `/admin/api/v1`. A trailing slash is removed                                                                                                                      | Matches how the issuer is configured everywhere else                               |
| Token on the command line | Not accepted (`--token` does not exist). `--token-file <file>` reads it from a file                                                                                                                                                                             | Command lines end up in shell history and process lists                            |
| Config file safety        | Warn on stderr if the config file holding a token is readable by group or others (POSIX only)                                                                                                                                                                   | Same idea as ssh                                                                   |
| Output                    | Default: lists (`items`) as a table of the item schema's scalar properties in schema order, arrays joined with `,`, cells cut at 40 characters; single objects as `key: value` lines; `204` prints nothing. `--json`: the response body as pretty JSON          | Readable by default, scriptable with `--json`                                      |
| Paging                    | List operations with a `cursor` parameter accept `--all`, which follows `next_cursor` and prints all items as one list                                                                                                                                          | `tunnus users list --all --json` for exports                                       |
| Errors                    | API errors print `<code>: <message>` and each detail (`path: message`) on stderr, exit 1. Network errors exit 1. Usage errors exit 2. Missing URL or token: exit 2 with a hint                                                                                  | Same error shape as the API                                                        |
| Destructive               | Operations with `x-tunnus-destructive: true` ask `Type yes to continue` on a TTY; without a TTY they need `--yes`, else exit 2                                                                                                                                  | Deletes and key changes cannot be undone                                           |
| Secret output             | `tokens create` prints the token value (`--json` or table); a note on stderr says it is shown once                                                                                                                                                              |                                                                                    |
| MCP transports            | `tunnus-mcp` (stdio, default) and `tunnus-mcp --http` (Streamable HTTP, stateless, `POST /mcp`). HTTP listens on `MCP_HOST` (default `127.0.0.1`) and `MCP_PORT` (default `8090`)                                                                               | stdio for local agents, HTTP for a shared deployment                               |
| MCP auth                  | stdio: the token from the same configuration as the CLI. HTTP: every request needs `Authorization: Bearer tun_...`, which is passed through to the admin API; the HTTP server holds no token of its own. Missing header → `401` with `WWW-Authenticate: Bearer` | The admin API stays the only place that checks tokens and audits                   |
| MCP tools                 | One tool per operation, named by `operationId`, plus commit-list tools (`getCommitList`, `executeCommitList`, `clearCommitList`), except operations with `x-tunnus-mcp: false`. Description = summary + description                                         | Destructive tools are guarded by the mutative commit-list/fixed-time lease; token values never enter an AI context |
| MCP mutative actions      | Guarded by CLI authorization: either staged into a commit list (`tunnus mcp allow commit-list`) or directly executed during an active fixed-time window (`tunnus mcp allow 15m`). Commit list can be executed on CLI (`tunnus mcp commit`) or by MCP (`executeCommitList`) when the fixed-time window is active | Operator controls mutative effects and reviews staged changes                     |
| Tool input                | One object: path and query parameters as top-level properties, the request body (if any) as `body`. `$ref`s are inlined so the schema is self-contained JSON Schema                                                                                             | MCP clients need a plain JSON Schema                                               |
| Tool annotations          | `readOnlyHint: true` for `get`; `idempotentHint: true` for `get`, `put`, `delete`; `destructiveHint: true` for `delete` and for `updateUser` (it can disable a user), else `false`; `openWorldHint: false`; `title` = summary                                   | Lets MCP clients ask before risky calls                                            |
| Tool results              | Success: `structuredContent` = response body (or `{}` for 204) and the same as JSON text. API error: `isError: true` with `<code>: <message>` and details as text                                                                                               |                                                                                    |
| Shared code               | `src/client/` holds what both use: config, the operation model and HTTP calls. `src/cli/` and `src/mcp/` hold the rest                                                                                                                                          | One HTTP client, one place that reads the spec                                     |
| Dependency                | `@modelcontextprotocol/sdk` (low-level `Server` with `ListTools`/`CallTool` handlers, so JSON Schemas from the spec are used as they are)                                                                                                                       | The official SDK; the high-level API wants Zod schemas                             |

## Structure

| File                       | Exports                                                                                                                                                                                                                                                       |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `src/client/config.js`     | `resolveConfig({ flags, env, readFile, stat })` → `{ url, token, source }`; pure apart from the injected file functions                                                                                                                                       |
| `src/client/operations.js` | `clientOperations(spec)` → one entry per operation: `operationId`, `command`, `method`, `path`, `summary`, `description`, `destructive`, `mcp`, `pathParams`, `queryParams`, `bodySchema` (refs inlined), `bodyRequired`, `paged`; `inlineRefs(spec, schema)` |
| `src/client/http.js`       | `createApiClient({ url, token, fetch })` with `call(op, { params, body })` → `{ status, body }`; throws `ApiError` (`status`, `code`, `message`, `details`) for non-2xx and for network failures (`code: network`)                                            |
| `src/cli/main.js`          | `main(argv, { env, stdout, stderr, stdin, isTTY, fetch, readFile, stat })` → exit code. Everything injectable for tests                                                                                                                                       |
| `src/cli/args.js`          | Flag definitions per operation and conversion of argv to `{ params, body }`                                                                                                                                                                                   |
| `src/cli/format.js`        | `formatTable(items, itemSchema)`, `formatObject(obj)`                                                                                                                                                                                                         |
| `src/client/mcpState.js`   | `loadMcpState`, `saveMcpState`, `allowFixedTime`, `allowCommitList`, `stageAction`, `isFixedTimeRunning`, `getFixedTimeRemainingMs`, etc.                                                                                                                   |
| `src/cli/mcpCommands.js`   | `handleMcpCli(words, rest, globals, io, operations, config)` → CLI `tunnus mcp allow`, `status`, `list`, `commit`, `clear`, `disallow`                                                                                                                         |
| `src/mcp/server.js`        | `createMcpServer({ spec, callApi, state, statePath })` → SDK `Server`; `mcpTools(spec)` → tool list with operations and commit-list tools                                                                                                                     |
| `src/mcp/http.js`          | `createMcpHttpApp({ spec, url, fetch, oauth, statePath, state })` → Express app serving `POST /mcp`                                                                                                                                                           |

## Tests

- Unit: every operation has a unique command; flag names do not collide
  within an operation; argv conversion for each value type, positional
  path parameters, `--body` merging and unknown flags; config precedence
  and file-permission warning; table and object formatting; the MCP tool
  list (destructive and `x-tunnus-mcp: false` operations absent, the rest
  present, annotations as in the table, schemas contain no `$ref`).
- Integration (against a running Tunnus from `test/helpers/admin.js`): CLI
  `whoami`, `users create`, `users list --json`, `groups create`,
  `groups grant`, `users delete --yes`, an API error and exit codes; MCP
  through the SDK `Client` over an in-memory transport, one call to every
  exposed tool; MCP HTTP with and without a bearer token.
